# Запуск Tickety внутри Telegram

## Постоянный адрес (основной способ)

**https://yaneponimaucheoniotmenyahotyat.github.io/tickety-twa/**

Этот адрес указан в @BotFather → Menu Button. Обновление — обычный push:

```bash
git add -A
git commit -m "что изменилось"
git push
```

GitHub Actions соберёт и выложит сайт примерно за минуту
(ход сборки — вкладка **Actions** в репозитории). Потом закройте и откройте Mini App.

## Проверка с сервером (бэкенд на этом компьютере)

Приложение и API идут через один туннель: Vite пересылает `/api` на `server/` (порт 8787).
Нужен токен бота в `server/.env` (`BOT_TOKEN=…`).

```bash
cd server
npm run public       # сервер; dev-вход выключен принудительно, без BOT_TOKEN не стартует
```

```bash
npm run phone:api    # сборка, которая ходит в API по тому же адресу
```

```bash
npm run tunnel:bot   # туннель + бот сам обновляет кнопку меню на текущий адрес
```

localhost.run без регистрации **меняет адрес** без предупреждения (старый пишет
«no tunnel»). `tunnel:bot` ловит каждый новый адрес и через Bot API
`setChatMenuButton` сразу ставит его в кнопку «Tickety» — в BotFather ничего
менять не нужно. **Ctrl+C** — туннель останавливается, кнопка возвращается на GitHub Pages.

Проверка: **Профиль → «О приложении» → «сборка local»**, строкой выше —
**«Аккаунт Tickety — вход подтверждён»**.

## Локальная разработка через туннель

Нужна, чтобы проверить правки на телефоне до push. Telegram открывает
Mini App только по **HTTPS**, поэтому локальный сервер выводится наружу через туннель.
Пока проверяете через туннель, в BotFather должен стоять адрес туннеля —
не забудьте вернуть постоянный.

## 1. Сервер + туннель (два терминала)

```bash
npm run phone        # сборка + раздача на 127.0.0.1:5173 — грузится ~4 с
```

Или, если нужны правки «на лету» (HMR и консоль Eruda), — dev-режим.
Он делает ~80 запросов, и бесплатный localhost.run тормозит каждый:
первая загрузка на телефоне — до минуты.

```bash
npm run dev:tunnel
```

```bash
npm run tunnel       # localhost.run: печатает https://<id>.lhr.life
```

Скопируйте адрес `https://….lhr.life` из второго терминала.
**Он меняется при каждом запуске `npm run tunnel`** — тогда повторите шаг 2.3.

> `npm run tunnel:cf` — запасной вариант через Cloudflare. У части российских
> провайдеров он не подключается (`TLS handshake with edge error: EOF`) — это DPI,
> помогает только VPN.

## 2. Бот в @BotFather (один раз)

1. `/newbot` → имя `Tickety Dev` → username, например `tickety_dev_bot`.
   Токен бота для Mini App не нужен — никому его не пересылайте.
2. `/mybots` → ваш бот → **Bot Settings** → **Menu Button** → **Configure menu button**.
3. Отправьте адрес туннеля `https://….lhr.life`, затем название кнопки: `Tickety`.

Альтернатива — `/newapp`: даёт ссылку вида `t.me/tickety_dev_bot/app`, но требует
картинку 640×360 и описание. Для разработки достаточно Menu Button.

## 3. Проверка на телефоне

Откройте бота → кнопка **Tickety** слева от поля ввода.
Пока грузится JS, показывается заставка с логотипом — пустого экрана быть не должно.

| Что проверить | Ожидаемо |
|---|---|
| Открытие | Сразу на весь экран, без белой вспышки |
| Тема | Переключите тёмную тему Telegram — фон и карточки меняются на лету |
| Фильтры → свайп вниз по списку | Шторка скроллится, Mini App **не** сворачивается |
| Свайп за ручку шторки | Шторка закрывается |
| Экран события | В шапке Telegram — нативная «Назад», своей кнопки нет |
| Нажатия на чипсы/кнопки | Лёгкая вибрация |
| «Открыть на карте» | Открывается внешний браузер/Карты, а не внутри Mini App |
| Оплата → закрыть Mini App | Telegram спрашивает подтверждение |
| Таймер брони | Свернуть Telegram на минуту → время не «застыло» |

**Консоль на телефоне:** только в `npm run dev:tunnel` — шестерёнка Eruda в углу
экрана (логи, сеть, DOM). В сборку `npm run phone` не попадает.

После правок в режиме `phone` перезапустите `npm run phone` и закройте/откройте
Mini App. Туннель перезапускать не нужно — порт тот же, адрес в BotFather прежний.
